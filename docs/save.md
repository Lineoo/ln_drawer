# 存档系统

## 1. 组成

存档由两部分构成，二者同级存放于数据目录（由 `LNDRAWER_RELEASE` 决定是 `LnDrawer` 还是 `LnDrawerDev`）：

1. **主库 `world.lndb`** - redb 数据库，只保存小体量状态：格式版本、紧凑标志、相机等。
2. **侧车区块存储 `chunks/`** - 画布区块数据，每区块一个独立文件。

## 2. 分离

区块具备以下性质，并不需要 redb 的事务保证：

- **不可变**，写入即定型
- 按 `(page, 区块坐标)` **单独定位**，从不跨键操作
- 读写天然分批、异步发生

## 3. 区块文件

- 路径为 `chunks/<page>/<x>_<y>_<z>.zst`，按路径直接命中，读取时不扫描目录。
- 每个文件自描述：开头是固定的 `magic` 与区块格式版本，随后是变长的 postcard 头部，压缩负载紧随其后。
- 写入是**原子**的（先写临时文件再重命名），崩溃不会产生半个区块。
- 透明（全空）区块不落盘，直接删除对应文件。

格式：

- 魔法 `LNCK` 4 bytes
- 区块格式版本 小端数字 4 bytes
- 头部长度 小端数字 4 bytes
- 头部内容 postcard
- 区块载荷 zstd 编码

开头的 `magic + 区块格式版本` 固定 8 字节永不改变，区块据此版本迁移；版本匹配后按头部长度读出 postcard 头部。

## 4. 版本与迁移

- **主库 `FORMAT_VERSION`** - 表与元数据布局，逐级迁移，版本高于当前则拒绝打开。
- **区块 `format` 字段** - 文件头与负载布局；读取时惰性迁移并回写，无法惰性完成的变更则主动遍历重写。

## 5. 备份

启动备份目前只覆盖体积很小的主库。**整库备份**（连同区块目录）已预留扩展点，但暂未实现。
